# 算法路线图（知识点图谱）体验优化

## 问题诊断

### 数据层面
- **331 个知识点**，3 层结构：7 根 → 95 二级 → 229 三级
- **"其他" 成了垃圾场**：数学/其他 75 个、图论/其他 29 个、数据结构/其他 19 个 — 这些是 OI-wiki 没分好类的零散内容，占了三级节点的一半以上
- **基础分类是平铺的**：26 个二级子节点混在一起，搜索算法(BFS/A*/回溯)、竞赛技巧(常见错误/读入优化)、基础概念(前缀和/滑动窗口) 全部平级
- **内容覆盖率高**：312/324 叶子节点有讲义，64 个有模板，仅 12 个为空

### UI 层面
1. **无搜索**：331 个节点，找一个知识点只能手动逐层展开
2. **无过滤**：不能按状态（已掌握/学习中/可学/锁定）或难度筛选
3. **默认全展开**：7 个根节点自动展开 → 首屏直接是几百行列表，视觉过载
4. **无分类级进度**：看不到"图论掌握 12/50"这样的分类汇总
5. **"其他"分类占据视觉焦点**：数学/其他 75 个子节点展开后屏幕占满
6. **纯树视图，无概览**：没有进度可视化，用户无法感知"整体走到哪了"

### 根本矛盾
用户说得对："不存在一个十全十美的分类"。OI-wiki 的分类是**内容导向**的（按主题相似性组织），但学习者需要的是：
- 我接下来该学什么？（路径视角）
- 我掌握了多少？（进度视角）
- 这个知识点在哪？（搜索视角）
- 有哪些简单/困难的？（难度视角）

**结论：不修分类，修 UX。让分类的重要性降低，让搜索/过滤/进度成为主要交互方式。**

## 改动方案

### 改动 1：搜索栏（实时过滤）
**文件**: `frontend/src/pages/KnowledgeTree.tsx`

在页面顶部统计条下方添加搜索输入框：
- 输入文字时实时过滤树节点（匹配 name）
- 匹配的节点自动展开其父链
- 不匹配的节点隐藏
- 搜索框带清除按钮
- 空搜索时恢复完整树

### 改动 2：状态过滤标签
**文件**: `frontend/src/pages/KnowledgeTree.tsx`

在搜索栏右侧添加 5 个过滤标签：
- `全部` | `学习中` | `可学习` | `已掌握` | `未解锁`
- 点击标签后，树中只显示该状态的节点（及其父链）
- 默认选中"全部"
- 与搜索可叠加使用

### 改动 3：默认折叠 + 分类级进度条
**文件**: `frontend/src/pages/KnowledgeTree.tsx`

- 默认只展开 7 个根节点，二级及以下全部折叠
- 每个根节点右侧显示分类级进度条：`█████░░░░░ 12/50`（绿条 + 灰条 + 数字）
- 进度条宽度固定 60px，直观展示该分类完成度

### 改动 4："其他"子分类降级处理
**文件**: `frontend/src/pages/KnowledgeTree.tsx`

- 名称为 `其他%` 的子节点，始终默认折叠（即使父节点展开）
- 在排序中降到最后（同层级内，"其他"排末尾）
- 视觉上用更浅的颜色（`text-gray-400`）表示这是未分类内容

### 改动 5：节点计数优化
**文件**: `frontend/src/pages/KnowledgeTree.tsx`

- 根节点显示总叶子数和已掌握数：`图论分类 [12/50]`
- 非根非叶节点显示直接子节点数：`树结构 (10)`
- 叶子节点显示讲义/模板徽章（保持现有逻辑）

## 不改动的部分
- 后端 API 和数据结构不变（分类taxonomy不改）
- 路径预览时间线保持现有实现
- 统计卡片保持现有实现
- 图例保持现有实现

   - 状态过滤标签能正确筛选
   - 默认只展开 7 个根节点
   - 根节点有进度条
   - "其他"子分类默认折叠且排在最后
